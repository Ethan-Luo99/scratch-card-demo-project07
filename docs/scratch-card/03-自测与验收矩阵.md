# 刮刮卡自测与验收矩阵

> 三端：H5（iOS Safari、Android Chrome、PC Chrome 鼠标）、微信小程序（开发者工具仅作冒烟，验收以真机为准）、App-vue（自定义基座，含一台可复现旧内核回退的设备或旧基座）。

## 0. 通用量化口径

- **基准占比（ground truth）**：测试模式下开放 debug 接口，对全尺寸 canvas `getImageData` 按 alpha≤24 逐像素计算真实擦除面积占比 `ratioRef`；算法输出 `ratio`。误差 `|ratio-ratioRef|` 必须 **< 5%**（绝对值），且阈值揭晓时 `ratioRef ≥ 45%`（不早于阈值前 5 个百分点误触发）。
- **跟手性**：触点中心与擦除圆斑中心距离 ≤ 2 CSS px。
- **帧率**：快速刮动 5s 平均 FPS ≥ 50（120Hz 机型 ≥ 90），单次 touchmove 处理 ≤ 8ms，无连续 3 帧 > 33ms。
- **揭晓时延**：达到真实 50% 面积到涂层完全清空 ≤ 400ms（含 120ms 采样间隔 + 260ms 动画）。
- **幂等**：一次刮卡周期内 `complete` 恰好触发 1 次。

## 3. 验收门禁

1. P0 用例三端全部通过；P1 通过率 ≥ 90% 且无集中在同一端；P2 有记录与规避结论。
2. T04（误差 <5%）、T25（move 内无 getImageData）、T22（真机结论）为硬性门禁，任一不过不得进入实现完成态。
3. 微信端所有「层级/性能」结论必须附真机录屏或 trace，开发者工具结果不算验收证据。
4. 性能 trace 保留：低端安卓 30s 刮动的 FPS/长任务记录；采样耗时日志。
5. 回归用例集：T01~T05、T08、T10、T13、T15、T17、T19、T24、T30（共 14 条冒烟集），后续每次改动全量跑。
