# 刮刮卡自测与验收矩阵

> 对象：H5、App-vue（非 nvue）、微信小程序，同一份 `pages/scratch/scratch.vue`。
> 卡片基准：750rpx×400rpx，阈值默认 55%，笔刷半径默认 22rpx，网格 36×20，alphaClear=25。
> 图例：P1=H5，P2=App-vue，P3=微信小程序；必测真机见 §4。每条给出**可量化验收标准**。

## 4. 真机覆盖最低要求

- P3 微信：1 台中低端安卓（如骁龙 6 系/4GB 内存）+ 1 台 iPhone（iOS 主流版本）。
- P2 App-vue：打安卓自定义基座真机 1 台（重点验 type=2d node 返回形态与 WebView 合成，对应风险 R2）。
- P1 H5：移动端 Safari/微信内置浏览器/安卓系统浏览器各 1 次；桌面 Chrome 验鼠标分支。
- 每台必跑：M-TOUCH-1/2/3、M-LIFE-1/2、M-DPR 对应档、M-ALGO-1、M-PERF-1。

## 5. 量化测量方法（怎么得到上面的数字）

- **坐标偏差**：在卡片 5 个定位点（四角+中心）点击，记录触点与实际擦除质心，取欧氏距离。
- **占比真值**：调试开关下在 settled 前对**整张物理画布**读一次 `getImageData`，统计 alpha<25 像素占比，作为真值 `T`；误差 = `|confirmedRatio - T| / T`。
- **帧率/长任务**：微信用开发者工具 Trace/真机调试；安卓 App 用 `adb shell dumpsys gfxinfo <pkg>`；H5 用 Chrome Performance 长任务与 FPS。
- **touchmove 耗时**：在适配层对「换算→擦除→网格」段打 `now()` 差值，上报 P50/P95。
- **生命周期**：用开发者工具「模拟后台」+ 真机 Home 键/锁屏；回收类用多任务压后台 + 打开其他大内存应用后返回。
- **网络**：开发者工具/系统代理模拟断网、高延迟（>3s）、请求失败；结算幂等查服务端日志计数。
- **DPR/尺寸**：`uni.getSystemInfoSync()` 打印 pixelRatio、windowWidth；M-DPR-4 用浏览器设备模拟与真机折叠/旋转。

## 6. 上线准入（DoD）

1. §1~§3 所有 ✔ 项在对应真机通过，无 P0/P1 缺陷。
2. M-ALGO-1 三端误差均 < 5%；M-PERF-1 中低端机帧率 ≥ 50fps 且无断笔。
3. 切后台/断网/多指/越界四类异常均有确定且不伪造结果的行为。
4. 结算上报在断网重试下服务端仅 1 条记录（幂等验证通过）。
5. 文档 02 中 R1~R13 每项至少有一个对应用例覆盖并留存证据。
