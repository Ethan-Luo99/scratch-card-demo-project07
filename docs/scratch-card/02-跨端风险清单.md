# 刮刮卡跨端风险清单

> 适用：uni-app Vue3（`@dcloudio/* 3.0.0-5020420260813003`）→ H5 / App-vue / 微信小程序。
> 每条按「风险描述 / 受影响平台 / 触发条件 / 验证方法 / 缓解措施」五段式展开，并附官方文档出处。
> 说明：本文撰写时离线，引用以官方文档**章节标题 + URL** 为准；微信小程序原生 API 文档（canvas/cover-view）同时是 uni-app 该组件在微信端的底层行为依据。凡标「以现网文档为准」处，编码前必须复核对应版本。

---

## R1. 旧版 `uni.createCanvasContext` / `wx.createCanvasContext` 在微信端已废弃

- **风险描述**：旧 Canvas 接口在微信小程序已被官方标记为「不再维护」，推荐使用 Canvas 2D；继续使用会面临同层渲染、新特性不支持、`canvasGetImageData` 仅异步回调、未来版本行为不保证等问题。
- **受影响平台**：微信小程序（主）；H5/App 旧接口虽可用但属同一套将弃用 API。
- **触发条件**：选用 `uni.createCanvasContext(id,this)` + `uni.canvasGetImageData` 方案时。
- **验证方法**：查微信官方文档「画布 | Canvas」（旧版接口章节带废弃/不再维护说明）：`https://developers.weixin.qq.com/miniprogram/dev/component/canvas.html` 与 `https://developers.weixin.qq.com/miniprogram/dev/api/canvas/wx.createCanvasContext.html`；在最新版微信开发者工具与真机上观察是否有废弃警告。
- **缓解措施**：统一选 `<canvas type="2d">` + `SelectorQuery.fields({node:true})` 取 node 的新接口（技术方案 §4-A）；旧接口只作为对照，不进实现。
- **官方出处**：微信《canvas 组件》《wx.createCanvasContext》（标注旧接口不再维护、推荐新版 Canvas 2D）；uni-app《画布 canvas》组件文档 `https://uniapp.dcloud.net.cn/component/canvas.html`。

## R2. H5 端 canvas 是真 DOM，小程序端 canvas 是原生/同层组件，行为差异

- **风险描述**：H5 与 App-vue 的 canvas 在 WebView DOM 内，可直接拿到 `HTMLCanvasElement`、事件坐标与层级都遵循 Web 模型；微信小程序的 canvas 是组件（新版 type=2d 同层渲染），节点必须通过 `SelectorQuery` 异步获取，不能 `document.getElementById`，事件与合成模型也不同。若代码假设「canvas 即 DOM」会在小程序取不到 node 或坐标错乱。
- **受影响平台**：微信小程序 vs H5/App-vue（跨端差异）。
- **触发条件**：直接操作 DOM、同步取节点、或用 H5 专有全局（`window.Image`/`window.devicePixelRatio`）而未做端适配时。
- **验证方法**：三端分别在 `onReady` 后打印 SelectorQuery 返回：H5 应得真实 canvas node，微信应得带 `getContext/createImage/requestAnimationFrame` 的 Canvas node；对照 uni-app《页面·SelectorQuery》`https://uniapp.dcloud.net.cn/api/ui/nodes-info.html` 与微信《SelectorQuery.fields》`https://developers.weixin.qq.com/miniprogram/dev/api/ui/SelectorQuery.fields.html`。
- **缓解措施**：所有 node/rect 获取收敛到适配层 `queryCanvasNode()`，仅依赖 uni API；createImage、dpr、rAF 全部走平台抽象（方案 §6.3/§8）；不直接 `document.*`。**编码前置 spike（门禁）**：在目标 alpha 版 App-vue 真机用 ≤30 行最小 demo 验证 `<canvas type="2d">` 的 SelectorQuery 能返回带 `getContext` 的 node；若该版本 App-vue 不返回 node，则适配层按端降级——App-vue 回退用其 WebView 内 canvas 节点获取 2D 上下文（或旧 `uni.createCanvasContext` 仅用于 App 端绘制，像素判定改异步 `uni.canvasGetImageData`），微信/H5 仍走 type=2d；三端渲染接口由适配层统一，保证算法层与模板不变。
- **官方出处**：uni-app《画布 canvas》《SelectorQuery》；微信《canvas》《SelectorQuery》。

## R3. `cover-view` 子组件嵌套受限，无法承载任意奖品图文

- **风险描述**：`cover-view` 是为覆盖原生组件而存在，其内部仅能嵌套 `cover-view`、`cover-image` 等受限标签（含受限 button），不能放普通 `view/text/image`、富文本、动画、复杂布局；若用「cover-view 盖 canvas 显示中奖文案」会在小程序渲染异常或标签不生效。
- **受影响平台**：微信小程序（主），App-vue 同类原生覆盖场景。
- **触发条件**：把奖品标题、图片、领奖按钮等普通组件放进覆盖在 canvas 之上的 `cover-view`。
- **验证方法**：按微信《cover-view》文档的「可嵌套组件」限制逐项验证：`https://developers.weixin.qq.com/miniprogram/dev/component/cover-view.html`；uni-app《cover-view》`https://uniapp.dcloud.net.cn/component/cover-view.html`。
- **缓解措施**：不使用 cover-view。改为「奖品普通 view 在下层 + type=2d 透明涂层在上层」，达标后卸载 canvas 再挂纯 view 结算层（方案 §5），从结构上消除覆盖需求。
- **官方出处**：微信《cover-view》（明确支持的嵌套标签与原生组件覆盖关系）；uni-app《cover-view》。

## R4. `transformPx:false` 导致样式 px 不再自动转 rpx，引发布局/坐标单位错乱

- **风险描述**：本项目 `manifest.json` 已设 `transformPx:false`，编译期不把 `px` 转成 `rpx`。若仍按旧习惯在样式里用 px 期望其随屏缩放，或在 JS 里把 px 直接当 canvas 像素，会在不同屏宽机型出现涂层尺寸/位置与卡片不一致。
- **受影响平台**：H5 / App-vue / 微信小程序（三端均受单位策略影响）。
- **触发条件**：模板样式混用 px 与 rpx；JS 中硬编码长度喂给 canvas，未经 `uni.upx2px` 换算。
- **验证方法**：在 320px、375px、414px 等不同逻辑宽度机型测涂层是否恰好铺满 750×400rpx 卡片；对照 uni-app《manifest.json 配置项·transformPx》`https://uniapp.dcloud.net.cn/collocation/manifest.html` 与《尺寸单位 rpx / uni.upx2px》`https://uniapp.dcloud.net.cn/api/ui/nodes-info.html`、`https://uniapp.dcloud.net.cn/tutorial/syntax-css.html`。
- **缓解措施**：样式统一 rpx；JS 数值长度一律 `uni.upx2px()` 显式换算成 CSS 像素；canvas 缓冲区再乘 dpr（方案 §8.2）。
- **官方出处**：uni-app《manifest.json》(transformPx)、《CSS/样式》rpx 说明、`uni.upx2px` API。

## R5. 触摸坐标到 canvas 内部坐标偏移（滚动 / 自定义导航栏 / 节点偏移）

- **风险描述**：用 `pageX-pageY` 手算偏移、或用缓存的固定左上角，会在页面滚动、自定义导航栏、安全区、键盘弹起后出现「笔尖与擦除点错位」。
- **受影响平台**：三端，App-vue/微信在沉浸式或自定义标题栏时更明显。
- **触发条件**：页面可滚动；使用自定义 navigationStyle；rect 只在 onReady 取一次后长期复用。
- **验证方法**：页面加滚动后在卡片四角与中心点击，观察擦除点是否在触点正下方；切换横竖屏/弹起键盘后复测。参考 uni-app《触摸事件 touchstart/touchmove/touchend》与微信《canvas 2D 获取节点及坐标示例》`https://developers.weixin.qq.com/miniprogram/dev/component/canvas.html`。
- **缓解措施**：统一用运行时 `boundingClientRect` 与 `clientX/Y`（或微信 touch 自带 `x/y`）相减；onShow/布局变化重取 rect；不使用固定常量偏移（方案 §8.3）。
- **官方出处**：uni-app《事件处理/触摸事件》；微信《canvas》（含 SelectorQuery 取节点、坐标换算官方示例）。

## R6. 页面切后台/被回收后 canvas 资源失效或画面清空

- **风险描述**：微信小程序切后台、WebView 回收或内存紧张时，Canvas 2D node/上下文可能失效或画布被清空，回到前台后笔迹/涂层丢失，若直接继续绘制会报错或画在失效上下文。
- **受影响平台**：微信小程序（最常见）、App-vue（WebView 回收）、H5（低内存/长时间挂起）。
- **触发条件**：刮到一半 `onHide`，停留较久或系统回收后再 `onShow`。
- **验证方法**：刮开约 40% 后切微信后台/锁屏 1~5 分钟、触发内存回收（开发者工具「模拟后台」+ 真机压测），再回前台观察画面与能否继续；生命周期参考 uni-app《页面生命周期 onShow/onHide/onUnload》`https://uniapp.dcloud.net.cn/tutorial/page.html`。
- **缓解措施**：onHide 取消计时器/rAF、冻结输入；onShow 重新 query node 校验有效性，失效则重绘涂层并按已确认网格「重放」历史擦除（网格状态常驻内存）（方案 §10）。
- **官方出处**：uni-app《页面生命周期》；微信《小程序生命周期 / onHide onShow》。

## R7. 高 DPR 下物理/逻辑像素未对齐导致笔迹发虚、读像素尺寸不符

- **风险描述**：未按 `canvas.width = cssW*dpr` + `ctx.scale(dpr,dpr)` 设置，会在 2x/3x 屏出现涂层模糊、擦除边缘毛糙，`getImageData` 宽高与网格划分不一致，占比算错。
- **受影响平台**：三端，高端 3x 安卓/iPhone 最明显。
- **触发条件**：漏设 width/height 属性、只改 style、或 dpr 取整/坐标换算不一致。
- **验证方法**：在 DPR=1/2/3 机型打印 `node.width/node.height/cssW/cssH`，核对比例等于 dpr；直线擦除边缘应锐利。参考微信《canvas 2D 适配高清屏（设置 canvas 宽高与 scale）》`https://developers.weixin.qq.com/miniprogram/dev/component/canvas.html`，uni-app《uni.getSystemInfoSync / uni.getWindowInfo》（`pixelRatio`）：`https://uniapp.dcloud.net.cn/api/system/info.html`。
- **缓解措施**：适配层统一初始化（方案 §8.1）；dpr 必要时 clamp 到 [1,3]；getImageData 的脏矩形物理坐标统一 round 并外扩 1~2px 吸收取整误差。
- **官方出处**：微信《canvas》高清屏适配示例；uni-app《uni.getSystemInfoSync / getWindowInfo》。

## R8. 在 touchmove 中同步 getImageData 导致中低端机掉帧/断笔

- **风险描述**：全图同步读像素触发 GPU→CPU 回读并阻塞主线程，高频 touchmove 下掉帧、触控延迟、笔迹断续。
- **受影响平台**：三端，中低端安卓 App/微信最严重。
- **触发条件**：每次 move 调 `getImageData` 全图扫描。
- **验证方法**：用开发者工具性能面板/微信 Trace 与 Android `adb shell dumpsys gfxinfo` 测帧率与长任务；对比「每帧读」与「节流脏矩形读」。
- **缓解措施**：热路径只做几何网格；像素读取消振到 ≥120ms + rAF、仅读脏矩形、门控到接近阈值才启用；touchend 补判（方案 §9）。
- **官方出处**：标准 Canvas2D `CanvasRenderingContext2D.getImageData()`（同步读回语义，见 MDN/HTML 规范）；微信《canvas 2D》同步 API 说明。

## R9. 多指触摸造成多点同时擦除/状态错乱

- **风险描述**：多指同时落下时 `event.touches` 含多个点，若遍历处理会产生交叉线段、P0 跳变；手指交替抬起还会让插值从错误点起跳。
- **受影响平台**：真机三端（模拟器多为单指，易漏测）。
- **触发条件**：双指/多指在涂层上滑动或交替触摸。
- **验证方法**：真机双指交叉、第二指点下后抬起第一指；验收矩阵 M-TOUCH-3。参考 uni-app/微信触摸事件中 `touches/changedTouches/touch.identifier` 定义。
- **缓解措施**：只跟踪首个手指（`identifier` 匹配的 changedTouches），忽略其余 touch；该指 touchend/cancel 才清空 P0。
- **官方出处**：uni-app《触摸事件》；微信《事件·触摸事件（touches/changedTouches/identifier）》。

## R10. 涂层底图跨域 / 解码失败 / 加载竞态

- **风险描述**：涂层用网络图时，H5 受跨域（未配 CORS 的图片会让画布被 `taint`，进而 `getImageData` 抛安全错误）；小程序需用 node.`createImage()` 且域名要在 downloadFile 合法域名；快速 reset 时旧图晚到导致覆盖新涂层（竞态）。
- **受影响平台**：H5（taint/跨域）、微信（合法域名/createImage）、App-vue。
- **触发条件**：涂层为远程图、域名未白名单、弱网慢加载、连点重置。
- **验证方法**：H5 用跨域图观察 `getImageData` 是否抛 SecurityError；微信开发者工具勾选/不勾选「不校验合法域名」对照真机。微信图片域名规则见《网络/域名白名单》与《canvas.createImage》`https://developers.weixin.qq.com/miniprogram/dev/component/canvas.html`。
- **缓解措施**：优先本地/纯色涂层；网络图走配置好的合法域名 + H5 设 `img.crossOrigin='anonymous'`；加载失败降级纯色；用请求序号/Abort 语义防止旧图回写（方案 §10、适配层 image.ts）。
- **官方出处**：微信《canvas》(createImage)、《开发设置·服务器域名》；HTML 规范 canvas 同源/tainted 安全模型。

## R11. 「先刮后取奖品数据」的发奖一致性与伪造中奖风险

- **风险描述**：若未先拿到结果就允许刮开，网络失败时无法展示真实奖品，弱网/重试可能重复发奖或前端被篡改伪造中奖。
- **受影响平台**：三端（业务逻辑层）。
- **触发条件**：进页面即开刮，奖品结果在刮完后才请求；请求失败或重复 complete。
- **验证方法**：断网刮卡、刮达标瞬间杀进程重进、连点领奖；核对服务端幂等记录。
- **缓解措施**：默认「先取到奖品结果（含 won 字段）再绘制涂层」；确需先刮则结果待定、达标后锁定结算层等待数据，禁止本地臆造中奖；结算带会话幂等键（方案 §10）。
- **官方出处**：uni-app《网络请求 uni.request》`https://uniapp.dcloud.net.cn/api/request/request.html`（失败回调/超时语义）。

## R12. 模拟器/开发者工具与真机渲染、性能、事件差异

- **风险描述**：微信开发者工具 canvas 合成、touch 频率、dpr、回收行为与真机不同；H5 桌面浏览器鼠标事件与真机 touch 不同；只在模拟器验收会漏掉真机层级与性能问题。
- **受影响平台**：全部（验证手段风险）。
- **触发条件**：仅在开发者工具/桌面浏览器测试后即发布。
- **验证方法**：每端至少 1 台中低端真机回归（安卓微信、iOS 微信、App 安卓包、H5 移动浏览器），保留性能 trace；验收矩阵单列「模拟器 vs 真机差异项」。
- **缓解措施**：H5 同时绑定 touch 与 mouse（或 pointer 特性检测），但判定逻辑只认统一归一化点；关键结论以真机为准（03 文档 M-DEVICE 系列）。
- **官方出处**：微信《开发者工具与真机差异》相关说明（以现网文档为准）；uni-app《各端差异注意事项》`https://uniapp.dcloud.net.cn/tutorial/matter.html`。

## R13. 抗锯齿/半透明像素与阈值抖动导致占比误判

- **风险描述**：擦除圆边缘与缩放产生半透明像素，单阈值（alpha<128）会把边缘计入面积，且同一像素在多帧间于阈值附近抖动，使 ratio 上下跳动、可能提前/延迟触发。
- **受影响平台**：三端（算法层）。
- **触发条件**：快速画大弧、低 dpr、频繁来回描同一区域。
- **验证方法**：构造已知长度线段，比对几何估计与像素复核 ratio；对角单划误差纳入验收 M-ALGO-1（<5%）。
- **缓解措施**：只认 alpha、严格透明阈值 25、迟滞双阈值（25/230）状态单向、块内多点聚合、脏矩形增量（方案 §7.4）。
- **官方出处**：标准 Canvas2D 合成与 `getImageData`（`globalCompositeOperation='destination-out'`、ImageData alpha 语义）。
